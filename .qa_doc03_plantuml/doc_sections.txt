073: 2.2.1 用例名：获取个人行程信息数据
074: 2.2.1.1 获取个人行程信息数据用例描述
075: 业务目标：旅客获取当前航班、机场、路线和旅客自身位置等个人行程信息，并了解数据的来源与更新时间。
076: 执行者：旅客（发起者）；数据来源（通过“数据处理分析”参与）。
077: 触发条件：旅客进入行程页面，或主动刷新个人行程信息。
078: 前置条件：系统服务可用；已存在可查询的行程；数据来源可访问或已有最近一次有效数据。
079: 基本交互动作：
080: 1. 旅客请求查看个人行程信息（或输入航班号/出行日期请求创建行程）。
081: 2. 系统识别当前行程及其涉及的航班、机场、路线和旅客位置。
082: 3. 数据处理分析获取并标准化相关数据，记录数据来源与更新时间。
083: 4. 系统返回并展示个人行程信息、缺失或降级状态。
084: 扩展交互动作：
085: 2a1. 数据来源不可用：使用最近一次有效数据并明确标注数据时间和降级状态。
086: 2a2. 定位不可用：允许旅客查看已有行程信息，并提示当前定位信息不可用。
087: 后置条件：旅客获取到带数据来源、更新时间和有效性的个人行程信息。
088: 业务规则：系统只展示有依据的数据，不虚构航班、机场、路线或位置状态。
089: 性能需求：请求应在可接受时间内返回；外部数据查询应设置超时。
090: 可靠性需求：单个数据源失败不影响其他行程信息展示。

094: 2.2.2 用例名：获取行程安排建议
095: 2.2.2.1 获取行程安排建议用例描述
096: 业务目标：旅客获取由系统生成的、基于当前行程状态和个人行程信息的下一步行动安排建议。
097: 执行者：旅客（发起者）；数据来源（通过“数据处理分析”参与）。
098: 触发条件：旅客查看行程安排建议，或行程状态发生变化后系统重新生成建议。
099: 前置条件：已获取个人行程信息；数据来源可用或已有最近一次有效数据。
100: 基本交互动作：
101: 1. 旅客请求获取行程安排建议。
102: 2. 系统读取当前行程信息与数据处理分析结果。
103: 3. 系统根据当前时间、旅客所处阶段和剩余时间生成有优先级的行动建议。
104: 4. 客户端展示建议、风险等级、建议依据和生成时间。
105: 扩展交互动作：
106: 2a1. 行程数据不完整或过期：使用最近一次有效数据并给出降级提示。
107: 2a2. 当前定位不可用：基于最近一次有效位置生成建议，并提示位置不确定性。
108: 3a. 系统无法确定下一步：明确提示旅客向航司或机场工作人员确认，不输出确定性结论。
109: 后置条件：旅客获得可解释、可执行的行程安排建议。
110: 业务规则：值机、登机等关键时间作为硬约束；系统不自动执行改签、支付等高影响操作。
111: 性能需求：建议生成应在可接受时间内完成，并支持数据变化后的及时更新。
112: 可靠性需求：数据缺失或接口异常时仍可展示基础提示，不因单点故障中断服务。

116: 2.2.3 用例名：获取行程延误风险
117: 2.2.3.1 获取行程延误风险用例描述
118: 业务目标：旅客获取航班延误、机场运行、交通和路径变化等因素导致的行程延误风险。
119: 执行者：旅客（发起者）；数据来源（通过“数据处理分析”参与）。
120: 触发条件：旅客查看行程风险，或航班、机场、路线等状态发生变化。
121: 前置条件：已获取个人行程信息；数据来源可用或已有最近一次有效数据。
122: 基本交互动作：
123: 1. 旅客请求获取行程延误风险。
124: 2. 系统读取当前航班、机场、路线、时间和旅客位置状态。
125: 3. 数据处理分析对最新数据进行标准化、校验和降级判断。
126: 4. 系统分析风险等级、主要风险因素和可能影响。
127: 5. 客户端展示风险等级、风险说明、数据来源和更新时间。
128: 扩展交互动作：
129: 2a1. 数据来源不可用：使用最近一次有效数据并明确提示风险判断时效有限。
130: 2a2. 航班或机场状态未知：标记为未知，不输出确定性延误结论。
131: 后置条件：旅客获取到有时间窗口和数据依据的行程延误风险。
132: 业务规则：风险展示以航班、机场和交通的最新可用数据为依据；无法确认时不夸大风险。
133: 性能需求：风险数据应按合理周期更新，数据变化后应及时重新分析。
134: 可靠性需求：外部数据异常或延迟时，系统应继续运行并显示最后更新时间。

138: 2.2.4 用例名：导航到机场
139: 2.2.4.1 导航到机场用例描述
140: 业务目标：旅客通过系统一键导航到机场，并在地图应用或浏览器不可用时获得清晰的替代提示。
141: 执行者：旅客（发起者）；外部地图导航应用（支撑系统）。
142: 触发条件：旅客查看行程信息或行动建议后，点击“导航到机场”。
143: 前置条件：已获取当前位置或最近一次有效位置；已确定机场目的地。
144: 基本交互动作：
145: 1. 旅客点击“导航到机场”。
146: 2. 系统读取当前位置、机场目的地和可用导航服务。
147: 3. 系统生成包含当前位置与机场目的地的导航地址。
148: 4. 系统跳转到地图导航应用；应用未安装时回退为浏览器打开导航网页。
149: 5. 返回系统后，客户端继续展示机场内值机、安检、登机口等文字指引。
150: 扩展交互动作：
151: 2a. 当前位置不可用：使用手动选择的位置或最近一次有效位置生成导航，并提示定位精度。
152: 4a. 导航跳转失败：提示旅客手动打开导航应用，不影响其他行程信息展示。
153: 后置条件：导航已启动或已提示旅客可用替代方式。
154: 业务规则：系统只负责跳转导航，不获取或保存导航过程中的轨迹；高影响操作仍需旅客确认。
155: 性能需求：点击导航后应尽快响应并完成跳转。
156: 可靠性需求：导航失败时应有明确提示，并保持行程状态持续更新。

160: 2.2.5 用例名：数据处理分析
161: 2.2.5.1 数据处理分析用例描述
162: 业务目标：数据来源向系统提供航班、机场、路线等原始数据，系统完成获取、标准化、校验和状态更新，为旅客直接使用的四个用例提供数据支撑。
163: 执行者：数据来源（发起者）。
164: 触发条件：旅客触发任一数据相关用例，或系统需要更新行程数据时。
165: 前置条件：系统服务可用；数据来源可访问或已有最近一次有效数据。
166: 基本交互动作：
167: 1. 系统向数据来源请求航班、机场、路线等数据。
168: 2. 数据来源返回原始数据或错误状态并检测。
169: 3. 系统对数据进行分析、标准化并识别缺失、过期或异常项。
170: 4. 系统记录数据来源、更新时间和数据质量状态。
171: 5. 处理后的数据供“获取个人行程信息数据”“获取行程安排建议”“获取行程延误风险”和“导航到机场”使用。
172: 扩展交互动作：
173: 1a. 数据来源不可用：系统使用最近一次有效数据并明确标注降级状态。
174: 2a. 数据格式或内容异常：系统记录问题并向旅客给出明确提示，不编造数据。
175: 后置条件：系统获得可使用或可降级的最新数据，并保留数据来源与更新时间。
176: 业务规则：数据处理分析是系统内部扩展用例，不自动执行改签、支付等高影响操作。
177: 性能需求：数据查询应设置超时；单个数据来源失败不应阻塞其他数据处理。
178: 可靠性需求：系统在数据缺失、延迟或异常时继续运行，并展示明确的质量提示。
