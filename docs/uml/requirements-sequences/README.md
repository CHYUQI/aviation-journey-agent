# 五个用例的顺序图

本组图按《软件需求规格说明书 需求分析优化版》中的五个用例绘制，以旅客操作、系统行为及可见结果表达交互，不包含协议、接口路径、程序名称或返回码。

| 图号 | 用例 | 文件名 |
| --- | --- | --- |
| 图2-2 | 创建行程 | `2-2_create_journey` |
| 图2-3 | 查看行程状态与建议 | `2-3_view_journey` |
| 图2-4 | 更新位置或确认所处环节 | `2-4_update_progress` |
| 图2-5 | 打开前往出发机场的地图 | `2-5_open_airport_map` |
| 图2-6 | 清除本机行程记录 | `2-6_clear_local_journey` |

每张图包含 PNG 图片、可缩放 SVG 图片及可编辑的 PlantUML 源文件。PNG 可直接插入 Word，SVG 适合缩放和印刷，修改 `.puml` 后可以重新导出图片。

生命线按分析类明确标注：`<<boundary>>` 表示边界类，`<<control>>` 表示控制类，`<<entity>>` 表示实体类。旅客为参与者；外部信息提供方和地图服务单独表示。五张图均保留边界、控制和实体的协作。

图中的虚线箭头表示对前一个消息的回应；双箭头表示无需旅客再次操作的后续交付。`alt` 表示互斥分支，`opt` 表示条件满足时发生的操作，`loop` 表示重复过程，`ref` 表示引用其他交互过程。

“行程处理”“行程查看”和“行程记录”是需求分析中的职责或信息概念，不指定程序组件或存储技术。图片作为独立文件交付，需求文档中原有插图位置保留。
